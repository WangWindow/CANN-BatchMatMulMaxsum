## User Scenarios & Testing *(mandatory)*

### User Story 1 - 差距的根因诊断（Priority: P1）

算子开发者需要一份基于实测数据的根因诊断：当前实现（判题 25.5 分档）与榜首逐点 5~10× 的差距，
究竟由哪些可归因的机制构成、各自量级多少、哪些是结构性的、哪些是参数性的。

**Why this priority**: 没有可信的归因，后续每轮优化都是赌博；诊断是所有改进的前提。

**Independent Test**: 用判题逐点数据（S9/S11）+ 本地可测指标（TFLOPS、吞吐、耗时分解）交叉验证，
每个根因都有"机制→可观测证据→量级估计"三段式结论。

**Acceptance Scenarios**:

1. **Given** 判题逐点用时与榜首用时（如 P8 160µs vs 17µs、P14 87µs vs 8µs），**When** 按形状族归类分析，**Then** 每个族的差距被分解为若干可归因机制（含量级与证据）；
2. **Given** 本地可测指标（如 8192³ 达 ~53 TFLOPS ≈ 峰值 15-25%），**When** 交叉验证，**Then** "计算单元空转"等结论有独立证据支撑，不与判题数据矛盾。

### User Story 2 - 改进框架与优先级（Priority: P2）

开发者需要一份可执行的改进框架：按"预期收益 × 置信度 ÷ 成本与风险"排序的改进方向清单，
每条含机制假设、验证方法与回退点。

**Why this priority**: 时间预算有限（截止 10/17），必须把力气投在收益/风险比最高的方向上。

**Independent Test**: 每个方向在本地或判题上都有明确的通过/否决判据，可在 1~2 轮内证伪。

**Acceptance Scenarios**:

1. **Given** 框架中的任一方向，**When** 执行其验证方法，**Then** 能在一个迭代内判定"有效/无效"并记录证据；
2. **Given** 两个方向的收益相近，**When** 比较风险与回退成本，**Then** 低风险者优先，且每次只引入一个可归因变化。

### User Story 3 - 首个行动项的落地（Priority: P3）

框架的首个高置信行动项（当前 = N 轴切分触发解耦，修复 P14/P15 类从未进入并行路径的缺陷）被执行并验证。

**Why this priority**: 框架的价值必须由第一个真实收益证明；该行动项已有完整设计与部分实现。

**Independent Test**: 本地 ns/小点 A/B 无回归 + 判题 P14/P15 用时下降。

**Acceptance Scenarios**:

1. **Given** 已实现的 N 轴切分机制，**When** 修复其触发条件（解除与经济性估时的耦合），**Then** 目标形状进入并行路径且其余点不劣化；
2. **Given** 修复后的版本，**When** 判题，**Then** 15/15 保持且总分提升。

### Edge Cases

- 差距最小的点（如 P5/P7 仅 1.5~2×）不投入结构性改造，避免为小收益引入大风险；
- 某些方向的收益依赖领先者的实现假设（无法直接观测），必须以"本实现可测的等价机制"重新表述；
- 本地计时为宿主口径、判题为设备口径：任何"本地变差"的结论必须标注口径，不得据此直接否决方向；
- 已否证方向（K 预重排等）不得重复尝试，除非有新证据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 诊断 MUST 覆盖全部 15 个测试点的差距，并按形状族（微型/小型/中型/大型/宽扁）归类；
- **FR-002**: 每个根因 MUST 给出"机制→可观测证据→量级估计"三段式，禁止只有结论没有证据；
- **FR-003**: 诊断 MUST 区分三类差距来源：结构性（数据通路/粒度/并行度上限）、参数性（阈值/切分门限）、固定开销（启动/同步链）；
- **FR-004**: 改进框架 MUST 按"收益 × 置信度 ÷ 成本与风险"排序，且每条含验证方法与回退点；
- **FR-005**: 框架 MUST 标注每条方向的"判题可验证性"（能否在一轮判题内判定）；
- **FR-006**: 首个行动项 MUST 在框架确认后进入实现，并保持既有 15/15 与零回归；
- **FR-007**: 全部结论 MUST 与判题实测数据一致（冲突时以判题为唯一真值）。
- **FR-008**: 交付判题前的验证 MUST 使用全量回归（seq15 + 244 矩阵 + soak + 核数变体）；MUST NOT 仅以代表性子集（快门禁）作为交付依据。

### Key Entities

- **测试点族**：按形状特征聚合的测试点分组（差距分析的基本单元）；
- **根因项**：一个可归因的差距来源（机制、证据、量级估计、所属分类）；
- **改进方向**：框架条目（机制假设、预期收益、置信度、成本、风险、验证方法、回退点）；
- **行动项**：经框架排序后进入实现的具体变更（一迭代一个）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 产出一份根因诊断：15 个测试点全覆盖，结构化后差距来源不超过 6 类，每类有证据与量级；
- **SC-002**: 产出改进框架：候选方向不超过 5 条，均可在一轮迭代内判定有效/无效；
- **SC-003**: 首项行动落地：目标点判题用时下降 ≥2× 且总分不降（15/15 保持）；
- **SC-004**: 诊断结论在后续 ≥2 个判题轮次中保持有效（不出现与实测相反的核心结论）。
- **SC-005**: 交付判题前完成全量回归（seq15 + 244 矩阵 + soak + 核数变体）且全绿；失败可一键回退（47dc041）。

## Assumptions

- 榜首实现的结构不可直接观测，诊断以"本实现的可测机制"为准，推断部分必须明示为假设；
- 判题用时为设备侧口径（既有实证）；本地计时为宿主口径，仅作 A/B 相对对照；
- 现行基线与回退点 = S9（15/15，25.7 分，commit 47dc041）；S11 已实现 N 轴切分机制但触发未生效；
- 时间预算：距截止（10/17 18:00）约 3 天，框架条目数量受此约束；
- 验证协议（2026-10-14 澄清）：取消快门禁，交付前置 = 全量回归全绿；
- 已积累的实验反例（K 预重排、L1 半区 2→4 等本地无收益）直接采纳为"已否证"，不再重复验证。
