# Contracts（更新版）: 诊断报告与改进框架的交付格式契约

**Feature**: 002-perf-gap-analysis | **Date**: 2026-10-14（第二轮更新）


本特性不改动任何对外/对内运行契约（`run_kernel` 与内部启动契约维持不变，见 001 特性文档）。
本条契约约束**交付物格式**：诊断报告、改进框架与行动项记录必须满足以下字段完整性。

## 诊断报告契约（必须包含）

```text
1. 差距画像表：族 | 点 | 现状用时 | 榜首用时 | 比值 | 差距性质
   —— 覆盖全部 15 点，按族聚合；（数据来源：最近一次判题）
2. 根因清单：每条 = 机制 | 可观测证据 | 量级估计 | 分类 | 置信度  （数量 ≤6）
3. 口径声明：数据口径（判题=设备侧、本地=宿主侧）、采样时间、版本 md5
4. 与历史结论的差异：若有（如"触发缺失"修正"est 低估"），须显式标注
```

## 改进框架契约（必须包含）

```text
每条方向：机制假设 | 预期收益 | 置信度 | 成本 | 风险 | 验证方法 | 回退点 | 判题可验证性
排序：按 收益×置信度÷成本风险；相邻收益时低风险优先
附加：已否证方向清单（含否证证据摘要），禁止重复投入
附加（第二轮新增）：互斥声明（fullload↔streamK 等）与叠加关系
```

## 行动项契约（扩展至第二批次 A2–A5）

```text
每行动项必须声明：对照用例集、通过判据（本地 + 判题双轨）、失败回退命令（commit 级）、
提交前门禁项（全量回归四件套：seq15 + 244 矩阵 + soak + 核数变体）、
捆绑提交声明（本轮提交包含的全部变化集及其量级证据）
```

## 判题轮次记录契约（第二轮新增）

```text
每轮判题必须归档（PLAN.md）：轮次 | kernel md5 | commit | 总分 | 逐点用时 | 核心结论 | 后续动作
同分/微差轮次须标注"噪声判定"结论，防止将平台噪声误归因为优化失效。
```

**违反上述格式** ⇒ 视为交付不完整（对应 SC-001/SC-002/SC-005 不达标）。
