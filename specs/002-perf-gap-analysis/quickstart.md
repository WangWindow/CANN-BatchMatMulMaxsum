# Quickstart: 性能差距诊断与改进框架 — 验证指南

**Feature**: 002-perf-gap-analysis | **Date**: 2026-10-14

验证本特性的三件事：诊断可信（有三口径证据）、框架可判定（每条一轮可验）、首项行动可落地。

## 1. 诊断可信性验证（US1）

```bash
# 判题数据：取最近一次判题逐点表（用户提供）与榜首列对比，填写差距画像表
# 本地利用率：8192³ 级别用例（p00）→ 计算 2*B*M*N*K / 设备耗时
cd build && ./batch_matmul_max_sum_custom p00_cases.txt        # 观察中位耗时
# 手算校验：TFLOPS ≈ 峰值×(15~25%)?   C 流量 ≈ B*M*N*8B ?   与"空转/往返"结论一致
```

**期望**：根因 A/B 的量级估计与实测同阶（±2× 内）；每条根因 ≥2 项证据。

## 2. 框架可判定性验证（US2）

对框架任取一条方向，按契约的"验证方法"执行，必须在一次迭代内得到有效/无效结论；
无验证方法或无法判定的方向 **不得进入框架**。见 [contracts/diagnosis-report.md](contracts/diagnosis-report.md)。

## 3. 首项行动验证（US3）

```bash
# 本地（快门禁协议）：
cd build
# a) 触发族目标用例（ns1/ns2/ns3）：正确性 + 设备口径间接证据
# b) 小点族对照（c00–c07）：确认未被误触发（本地 A/B 不变差即可）
python3 ../scripts/chk.py ../build/ns_cases.txt
# 判题：提交后对比 P14/P15 用时（期望 ≥2× 下降）与其余点（期望不变差）
```

**期望**：15/15 保持；P14/P15 用时显著下降；小点不劣化；总分提升。
**失败回退**：`git checkout 47dc041 -- kernel.asc`（S9 基线）。
