# Phase 0 Research: N 轴并行切分与最大值合成

**Feature**: 001-naxis-split-combine | **Date**: 2026-10-14

本文件把所有技术未知项收敛为可执行决策；全部结论均可由既有判题/本地实证支撑或本地可验证。

## R1 — 触发判定：何时进入 tile 级（N 轴）切分？

- **Decision**: `tileSplit = (blockCount > workItems)`（核内可由既有参数推导，零新增接口）。
  宿主侧 `blockCount` 在切分启用时改为 `min(可用核数, workItems × nShards)`。
- **Rationale**: 现有 M 轴切分保证 `blockCount ≤ workItems`；当宿主给出的 `blockCount` 大于
  workItems 时，唯一可能的并行维度就是 N 轴。该布尔量在宿主与内核两侧公式一致、无新参数。
- **Alternatives considered**:
  - 新增内核参数传递标志 → 违反"维持 14 参数"的判题风险纪律（历史全挂批次的嫌疑项之一），拒绝；
  - 宿主计算触发阈值并传入 → 同上；
  - 由 N 切片数单独判定（如 `nShards ≥ K`）→ 与核数无关，无法保证"有并行度可用"，拒绝。

## R2 — 工作划分与 tile 定义

- **Decision**: 定义扁平 tile 索引 `flat = (b × mTiles + mTileId) × nShards + nShardId`，
  按连续区间分配给各块（与 AIC/AIV 完全一致的整数公式，32 位安全）。
- **Rationale**: 与现有"工作项区间划分"同构、可并行可归约；tile 是"计算与部分结果产出的最小单位"，
  且与既有单 tile 流水（k 分块→矩阵乘→搬出）一一对应，单 tile 内部流水不需要任何改动。
- **Alternatives considered**:
  - 维持 (b, mTile) 工作项、块内再做 N 循环 → 并行度不增加，达不到 ≥2× 目标，拒绝；
  - N 轴只做两级（片组）→ 复杂度不降反升且并行度粒度变差，拒绝。

## R3 — 部分结果（逐行最大值）的存放

- **Decision**: 追加到既有 C 环工作区尾部的部分结果区：
  `r[blockIdx][b][mTileId][m]`，`m < partialStride`；按触发条件约束其规模（≤ 194KB）。
- **Rationale**: 复用既有工作区 = 不新增对外参数、不新增设备内存管理路径；规模上界由触发条件
  （workItems < 核数 ⇒ batch×mTiles ≤ 19）与 `partialStride ≤ 128` 共同保证。
- **Alternatives considered**:
  - 独立 GM 缓冲（新增指针参数）→ 违反参数纪律，拒绝；
  - 写回 C 环槽位复用 → 会与 AIC 生产时序耦合，存在覆盖窗口风险，拒绝。

## R4 — 合成同步：如何判定"全部部分结果已就绪"？

- **Decision**: 设备侧原子计数 + 轮询 + 幂等直写：
  1) 每块（双子核各自）在写完部分结果后，用既有 `SetAtomicAdd` 语义对共享计数器 +1；
     写入顺序与部分结果同队列（先部分结果、后计数），由硬件队列先出约束保证；
  2) 每块轮询计数器（GM 读取 + 标量判断循环）直到达到 `2 × blockCount`（双子核各一次）；
  3) 随后每块**冗余地**计算全部 batch 的最终分数并**直写** y（相同值重复写 = 幂等，无原子、无需清零）。
- **Rationale**: 该方案只使用项目已实证的要素：`SetAtomicAdd` 写入（既有 y 原子路径）、
  同队列写序（既有屏障回执的时序证据）、L2 作为一致性汇聚点（GM 流量与原子共享同一汇聚层）。
  以"幂等直写"替代"原子累加"，避免重复累加与预清零依赖（FR-003）。
- **Alternatives considered**:
  - 跨块全局屏障（FFTS mode-0 语义的核间大规模同步）→ 引入全新同步机制，判题风险不可控，拒绝；
  - 第二个内核做合成 → 新增 `__global__` 内核（历史嫌疑项"kpad 类"），拒绝；
  - 原子最大值（若硬件无 float 版）→ 不可用且依赖预初始化，拒绝。
- **Local risk retirement**: 轮询与写序的正确性在本地以"重复执行 + soak"验证（错误会表现为
  偶发错值或挂死，两种都在门禁覆盖内）。

## R5 — 触发阈值与并行度下限的标定

- **Decision**: 结构规则为主（R1），复用既有 `estPreUs ≥ 12µs` 的切分门槛作为"值不值得切"的经济性判据；
  N 切片数不足以覆盖核数时自然降级（部分块范围为空时不产出——需以"空范围不参与计数"的记账保证）；
  实现后在本地对 B=1/M≤128/N 大 的合成用例（新造 2–3 条）实测标定与回归。
- **Rationale**: 已有数据表明该类形状 est ≥ 12µs（S5b 起 doSplit=true 但受 workItems=1 阻塞），
  阈值不需要新机制；空范围记账是正确性硬要求（否则计数永不达标 ⇒ 挂死）。
- **Alternatives considered**: 全新收益模型 → 超出本特性范围（属 ⑥ 微调类），拒绝。

## R6 — 目标形状的本地代表用例

- **Decision**: 新造 3 条本地用例覆盖目标类与边界：
  `ns1 = (B=1, M=64, N=8192, K=512)`（典型目标类）、
  `ns2 = (B=1, M=8, N=2048, K=2048)`（M 极小、N 中）、
  `ns3 = (B=2, M=128, N=512, K=1024)`（临界多工作项），
  并各生成 FP64 金标；同时保留既有 244 矩阵与 soak 作为回归。
- **Rationale**: 判题 P14/P15 形状未知，本地以"结构等价类"覆盖（workItems=1 与临界 2–4）；
  金标生成沿用既有脚本（`scripts/BatchMatmulMaxSum.py` 的 `impl`）。
- **Alternatives considered**: 直接等判题反馈 → 违反快门禁纪律（盲提交），拒绝。
