# Feature Specification: N 轴并行切分与最大值合成

**Feature Branch**: `001-naxis-split-combine`

**Created**: 2026-10-14

**Status**: Draft

**Input**: User description: "攻④：N 维切分 + 两阶段合成 —— 让 batch×M 分块不足以铺满核数的形状（P14/P15 类）拿到 N 轴并行，收敛单点 10.7×/6.6× 的差距；零新增契约参数、幂等合成、不破坏已 15/15 的正确性"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 目标形状获得 N 轴并行（Priority: P1）

算子使用者提交一个 "batch×M 分块不足以铺满核数" 的形状（典型：batch 小、M 不超过单块行数、N 较大），算子仍能把 N 轴的切片工作分散到多核执行，整体耗时显著下降；输出与参考实现一致。

**Why this priority**: 这是当前评分表剩余最大的单点差距来源（P14 约 10.7×、P15 约 6.6×，合计 +6~9 分潜力），也是唯一尚未被利用的并行维度；现有 M 轴并行对该类形状是无效操作。

**Independent Test**: 用目标形状类（如 B=1、M≤128、N 大）的单条用例，对比改动前后的耗时与逐值正确性，即可独立验证本故事的 MVP 价值。

**Acceptance Scenarios**:

1. **Given** 一个 batch×M 分块不足以铺满核数的目标形状，**When** 执行算子并与 FP64 参考比对，**Then** 输出在 1e-4 容差内逐值一致，且设备口径耗时相比现状至少下降 2×；
2. **Given** 同一目标形状在不同可用核数（1/4/20/32）与重复执行（≥20 次）下，**When** 执行，**Then** 结果逐值一致、无挂死、无与运行次数相关的漂移。

---

### User Story 2 - 既有全部形状零回归（Priority: P2）

已通过的全部形状（含大/中/小、四种存储布局、两种数据类型、各类尾块）在引入本特性后行为不变：数值逐值一致、耗时不变差、并发/重复运行稳定性保持。

**Why this priority**: 当前版本是判题 15/15 / 分数 25.7 的高价值基线，任何回归都会直接损失既有分数与排名。

**Independent Test**: 运行既有全量回归资产（244 例矩阵 + soak + 核数变体），与基线逐例比对。

**Acceptance Scenarios**:

1. **Given** 既有 244 例回归矩阵，**When** 执行新版本，**Then** 结果与基线逐例一致（含既有的域外 K 守卫拒绝行为）；
2. **Given** soak 高频用例集合，**When** 重复 20 次独立进程执行，**Then** 零错值、零挂死。

---

### User Story 3 - 可解释、可回退的交付（Priority: P3）

本次改动以"相对上一判题版本的受控变化"交付：带版本标记与校验值，失败可一键回退到上一判题实证版本。

**Why this priority**: 团队工作纪律要求每次提交都能归因、能回退；这保证实验成本可控。

**Independent Test**: 检查交付物（源码标记、md5、提交记录、回退命令）是否齐备且有效。

**Acceptance Scenarios**:

1. **Given** 本特性的交付版本，**When** 核对交付三件套（文件+md5+核对方法），**Then** 与仓库内容一致且可复现；
2. **Given** 判题结果不达预期，**When** 执行回退命令，**Then** 回到上一判题实证版本（S9 基线）。

---

### Edge Cases

- **并行度不足**：N 轴切片数甚至不足以覆盖核数时，特性不得触发或需优雅退化（正确性优先，不强行切分）；
- **单切片退化**：某 (batch, m 行) 集合只落在单一并行单元内时，结果必须与现有路径完全等价；
- **极端尾块**：N 非整片、M=1、B=1、K 未对齐等组合下仍满足 1e-4 容差；
- **跨启动状态**：同一进程内多次执行、独立进程重复执行，均不得残留上一轮的状态；
- **合成可见性**：所有并行单元的部分结果全部就绪之前，不得进入合成；合成过程重复执行（幂等）不得产生重复累加；
- **域外输入**：既有守卫（K 非 8 倍数、K<32 等）行为保持不变（拒绝且不启动）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 对 "batch×M 分块不足以铺满核数" 的目标形状，算子 MUST 将 N 轴切片的工作分散到多核并行执行，且触发判定 MUST 仅依赖既有契约输入（不得新增对外参数或接口变化）；
- **FR-002**: 每个并行单元 MUST 只产出其 N 切片上的"逐 (batch, m 行) 最大值"部分结果；最终每个 batch 的分数 MUST 按参考语义合成：先对同一 (batch, m 行) 跨所有切片取最大值，再对 m 行求和（顺序不可交换）；
- **FR-003**: 合成 MUST 为幂等写（相同值重复写无害），MUST NOT 依赖预先清零的共享累加器，也 MUST NOT 使用会产生重复累加效果的写入方式；
- **FR-004**: 非目标形状 MUST 走与现状完全相同的执行路径，数值与性能不劣化（耗时差异限于噪声）；
- **FR-005**: 部分结果与就绪信号的存放 MUST 复用既有设备侧工作区；对判题契约入口的签名与调用方式 MUST 保持不变；
- **FR-006**: 域内所有形状（B≤64、M/N≤8192、32≤K≤8192 且 K 为 8 的倍数、四种存储布局组合、fp16/bf16）的输出 MUST 满足 fp32 下相对/绝对误差均 <1e-4；
- **FR-007**: 跨启动 MUST 无状态残留（同一进程多次与独立进程重复的执行结果一致）；
- **FR-008**: 并行单元之间 MUST 不存在"读到未就绪部分结果"的窗口；部分结果与其就绪信号的写入顺序 MUST 由既有硬件完成顺序保证（先数据、后就绪），合成方 MUST 在观察到全部就绪后才读取。

### Key Entities

- **工作项**：现有并行单元，由 batch 与 M 分块构成；本特性在其之上引入更细的 tile 级划分；
- **tile**：(batch, m 分块, N 切片) 三元组，是计算与部分结果产出的最小单位；
- **部分结果（行最大值）**：每个并行单元对自己负责的 N 切片，为每个 (batch, m 行) 产出的逐行最大值；
- **合成结果**：每个 batch 的最终分数（跨切片行最大值合并 + 对 m 行求和）；
- **就绪计数**：全局共享的进展信号，标识所有并行单元的部分结果均已写入完毕。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 目标形状类的单点耗时（判题侧设备口径）相比现状至少下降 2×；其余测试点耗时不变差（超过 ±2% 噪声即视为回归）；
- **SC-002**: 判题全量通过 15/15 且总分不下降；目标总分从 25.7 至少提升 +2；
- **SC-003**: 本地全量回归：244 例矩阵零值错误、soak（≥6 用例 × 20 次独立进程）零挂死零错值、可用核数 1/4/20/32 全部通过；
- **SC-004**: 交付前快门禁（标准 15 例 + 代表性子集）可在 5 分钟内给出通过/不通过结论，失败可一键回退。

## Assumptions

- 目标形状判定默认采用"工作项数 < 可用核数，且 N 轴切片可提供有意义并行度"（精确阈值按实测标定，允许后续微调）；
- 部分结果与就绪计数复用既有设备侧工作区（规模按触发条件约束，上界可接受）；
- 判题用时为设备侧口径（由历史判题数据推定：单核→多核耗时比与宿主开销不计入的实证）；
- 上一判题实证版本（S9，15/15，25.7 分）作为基线与回退点；
- 本地验证资产（标准 15 例、244 例矩阵、soak、核数变体）可信，且与判题结果长期一致；
- 同轮改动遵循"一次只引入一个可归因变化"的团队纪律。
